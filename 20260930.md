No MicroK8s, os comandos do Kubernetes são gerenciados pela CLI integrada. Para facilitar a sintaxe dos comandos nesta aula, configure um alias no terminal:

```bash
alias kubectl='microk8s kubectl'

```

---

## 1. Inspeção de Nós no Cluster

O **Node** é o servidor (físico ou virtual) onde o runtime do Kubernetes é executado e onde as cargas de trabalho residem.

* **Listar todos os nós:**
```bash
kubectl get nodes
kubectl get nodes -o wide  # Exibe dados extras (IPs internos/externos, SO, versão do runtime)

```


* **Verificar recursos e saúde detalhada do nó:**
```bash
kubectl describe node <nome-do-node>

```


*O `describe` no nó exibe uso de CPU/memória, capacidade alocável, condições do sistema (pressão de disco/memória) e eventos recentes.*

## 2. Objetos Principais do Kubernetes

### Pod

A menor e mais fundamental unidade no Kubernetes. Representa um único processo em execução e engloba um ou mais containers que compartilham a mesma rede (IP), armazenamento e namespace.

* **Quando usar:** É o bloco básico de construção. Raro ser criado diretamente em produção; costuma ser gerenciado por controladores.
* **Comandos:**
```bash
kubectl get pods
kubectl get pods -A                           # Em todos os namespaces
kubectl describe pod <nome-do-pod>             # Exibe eventos, IP, status dos containers e erros

```



### ReplicaSet

Controlador responsável por garantir que o número exato de réplicas de um Pod esteja sempre em execução no cluster. Se um Pod cai, o ReplicaSet recria um substituto imediatamente.

* **Quando usar:** Gerenciado de forma transparente pelo *Deployment*.
* **Comandos:**
```bash
kubectl get replicasets                       # Ou 'kubectl get rs'
kubectl describe replicaset <nome-do-rs>

```



### Deployment (Deploy)

Controlador de alto nível para aplicações sem estado (*stateless*). Ele gerencia a criação e atualização dos ReplicaSets, oferecendo mecanismos de atualização gradual (*rolling updates*), pausa e *rollback* de versões sem interrupção de serviço.

* **Quando usar:** Aplicações web, APIs REST e microsserviços sem necessidade de persistência associada a uma réplica específica.
* **Comandos:**
```bash
kubectl get deployments                       # Ou 'kubectl get deploy'
kubectl describe deployment <nome-do-deploy>

```



### Service

Prover um ponto de acesso fixo (com IP virtual e registro DNS interno) para expor um conjunto de Pods dinâmicos. Como os Pods sobrem e descem mudando de IP, o Service atua como balanceador de carga estável.

* **Tipos comuns:** `ClusterIP` (somente interno), `NodePort` (porta aberta nos nós), `LoadBalancer` (integrado à nuvem).
* **Comandos:**
```bash
kubectl get services                          # Ou 'kubectl get svc'
kubectl describe service <nome-do-service>     # Exibe os Endpoints associados (IPs dos Pods ativos)

```



### DaemonSet

Garante que uma cópia idêntica de um Pod seja executada em **todos** (ou em um grupo filtrado de) nós do cluster. Sempre que um novo nó entra no cluster, o Pod é adicionado automaticamente a ele.

* **Quando usar:** Agentes de logs (Fluentd, Logstash), agentes de monitoramento (Prometheus Node Exporter) ou roteamento de rede.
* **Comandos:**
```bash
kubectl get daemonsets                        # Ou 'kubectl get ds'
kubectl describe daemonset <nome-do-ds>

```



### StatefulSet

Controlador para aplicações com estado (*stateful*). Ao contrário do Deployment, cada Pod de um StatefulSet recebe uma identidade fixa e sequencial (ex: `db-0`, `db-1`), mantendo seus volumes e identificadores persistentes mesmo se for recriado.

* **Quando usar:** Bancos de dados (PostgreSQL, MySQL, MongoDB) e sistemas de mensageria em cluster (Kafka, RabbitMQ).
* **Comandos:**
```bash
kubectl get statefulsets                      # Ou 'kubectl get sts'
kubectl describe statefulset <nome-do-sts>

```



### CronJob (e Job)

Um **Job** executa um trabalho pontual até sua conclusão e encerra o Pod. O **CronJob** agenda a criação repetida de Jobs com base em expressões temporais estilo cron (`* * * * *`).

* **Quando usar:** Tarefas programadas, geração de relatórios diários, rotinas de limpeza ou execução de rotinas de backup.
* **Comandos:**
```bash
kubectl get cronjobs                          # Ou 'kubectl get cj'
kubectl get jobs
kubectl describe cronjob <nome-do-cronjob>

```

## 3. Guia de Uso: `kubectl get` vs `kubectl describe`

| Comando | Foco | Saída Principal | Uso Recomendado |
| --- | --- | --- | --- |
| **`kubectl get`** | Visão geral e listagem | Tabela concisa com nomes, status, réplicas e tempo de vida. | Validar rapidamente o estado dos recursos ou extrair dados brutos em formato YAML/JSON (`-o yaml`). |
| **`kubectl describe`** | Diagnóstico detalhado | Documento completo com labels, IPs, volumes, portas e **Eventos recentes**. | Descobrir por que um recurso falhou (`ImagePullBackOff`, `CrashLoopBackOff`, falta de memória no nó). |

## 4. Sequência Prática de Depuração

Ao se deparar com uma falha em uma aplicação rodando no MicroK8s:

1. Listar recursos para localizar falhas de status:
```bash
kubectl get pods

```


2. Inspecionar as causas e histórico do objeto com problema:
```bash
kubectl describe pod <nome-do-pod>

```


3. Ler as saídas de terminal geradas pela aplicação:
```bash
kubectl logs <nome-do-pod>

```
