### 1. Principais Objetos do Kubernetes

#### **Pod**

* **O que é:** É a menor unidade implantável no Kubernetes. Um Pod envolve um (ou ocasionalmente mais de um) contêiner que compartilha o mesmo IP, espaço de rede e volumes de armazenamento.
* **O que podemos fazer com ele:** Executar uma instância de aplicação de forma direta, inspecionar logs de sistemas, rodar comandos de diagnóstico (`kubectl exec`) e testar configurações rapidamente.

#### **Deployment**

* **O que é:** É um controlador declarativo que gerencia o ciclo de vida dos Pods através de *ReplicaSets*. Ele garante que o número desejado de réplicas de um Pod esteja sempre rodando.
* **O que podemos fazer com ele:** Escalar aplicações (aumentar/diminuir réplicas), fazer atualizações sem parada (*rolling updates*), reverter para versões anteriores (*rollbacks*) e garantir alta disponibilidade (substituição automática de Pods com falhas).

#### **Service**

* **O que é:** É uma abstração de rede que fornece um ponto de acesso estável (IP fixo e nome de DNS) para um conjunto dinâmico de Pods.
* **O que podemos fazer com ele:** Balancear carga de tráfego entre Pods, expor aplicações internamente no cluster (`ClusterIP`) ou para redes externas (`NodePort`, `LoadBalancer`).

### 2. O Pod em Detalhes

No YAML de especificação de um Pod, três seções se destacam:

* **Nome (`metadata.name`):** A identidade única do Pod dentro do Namespace.
* **Portas (`ports.containerPort`):** Declara a porta em que a aplicação dentro do contêiner está escutando. Funciona como documentação explícita e mapeamento de comunicação para o cluster.
* **Volumes (`spec.volumes` e `spec.containers.volumeMounts`):**
* `volumes` (nível do Pod): Define a origem do armazenamento (ex.: `hostPath`, `emptyDir`, `persistentVolumeClaim`).
* `volumeMounts` (nível do contêiner): Especifica em qual diretório *dentro* do contêiner o volume selecionado será montado.

### 3. Roteiro Prático de Laboratório

Substitua **`aluno`** ou **`seunome`** pelo seu nome real e **`80XX`** pela porta definida pelo professor (ex.: `8010`).

#### Passo A: Copiar o template existente

```bash
cp /tmp/template.yaml /tmp/seunome.yaml

```

#### Passo B: Estrutura do arquivo `seunome.yaml`

Edite o arquivo `/tmp/seunome.yaml` (usando `nano`, `vim` ou seu editor preferido) para deixá-lo com a estrutura abaixo:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-seunome
  labels:
    app: meu-app
spec:
  containers:
    - name: nginx-container
      image: nginx:latest
      ports:
        - containerPort: 80XX
      volumeMounts:
        - name: meu-volume-local
          mountPath: /usr/share/nginx/html
  volumes:
    - name: meu-volume-local
      hostPath:
        path: /tmp/seunome
        type: Directory

```

#### Passo C: Criar o diretório e o arquivo HTML de teste no Host

```bash
# 1. Criar a pasta do aluno
mkdir -p /tmp/seunome

# 2. Criar o arquivo index.html dentro da pasta
echo "Nome do Aluno" > /tmp/seunome/index.html

chmod 755 /home/aluno
chmod 755 /tmp/seunome
chmod 644 /tmp/seunome/index.html

```

#### Passo D: Aplicar, Verificar e Limpar

```bash
# 1. Criar o Pod no Kubernetes
kubectl apply -f /tmp/seunome.yaml

# 2. Verificar o status do Pod
kubectl get pod

# 3. Testar 
curl localhost:porta

# 3. Remover o Pod após a validação
kubectl delete -f /tmp/seunome.yaml

```
