# Kubernetes: Introdução ao Formato YAML

Seja bem-vindo à aula de introdução ao **YAML** (*YAML Ain't Markup Language*). No ecossistema Kubernetes, o YAML é o formato padrão para definir a estrutura de dados e declarar a configuração de todos os recursos do cluster.

---

## 1. Regras de Formatação e Sintaxe Básica

O YAML é uma linguagem baseada em indentação e legibilidade humana. As regras fundamentais de formatação são:

* **Indentação com ESPAÇOS**: **Nunca utilize a tecla `TAB**`. A convenção padrão é usar **2 espaços** por nível de indentação.
* **Sensibilidade a maiúsculas/minúsculas**: `nome` e `Nome` são chaves distintas.
* **Espaçamento obrigatório**: Deve haver um espaço após os dois-pontos em estruturas de chave-valor (`chave: valor`).

### Estruturas Fundamentais

#### Dicionários (Maps / Objetos)

Agrupamentos de pares chave-valor.

```yaml
aluno:
  nome: Ana Silva
  idade: 22
  ativo: true

```

#### Listas (Arrays / Sequências)

Elementos representados por um hífen `-` seguido de espaço.

```yaml
disciplinas:
  - Docker
  - Kubernetes
  - Linux

```

#### Tipos de Dados Comuns

```yaml
texto: "Hello World"   # String (aspas são opcionais, mas recomendadas se houver caracteres especiais)
inteiro: 100           # Number
decimal: 9.5           # Float
booleano: true         # Boolean (true/false em minúsculo)
nulo: null             # Null

```

#### Blocos de Texto Multi-linha

* `|` (Pipe): Preserva as quebras de linha exatas.
* `>` (Maior que): Junta as linhas em um único parágrafo.

```yaml
descricao_exata: |
  Primeira linha.
  Segunda linha.

descricao_continua: >
  Este texto será formatado
  como uma única linha contínua.

```

## 2. Ferramentas para Validar e Formatar YAML

Validar a sintaxe antes de aplicar qualquer arquivo evita falhas de execução no Kubernetes.

### A. Validação na Linha de Comando (CLI)

1. **`yamllint`** (Linter completo para terminal):
```bash
# Instalação (Ubuntu/Debian)
sudo apt install yamllint

# Instalação (macOS via Homebrew)
brew install yamllint

# Uso
yamllint meu_arquivo.yaml

```


2. **`python3`** (Validador nativo de sintaxe, sem instalações extras):
```bash
python3 -c 'import yaml, sys; yaml.safe_load(sys.stdin)' < meu_arquivo.yaml

```



### B. Extensões de Editor (VS Code)

* **YAML Extension (by Red Hat)**: Fornece destaque de sintaxe, validação em tempo real e auto-formatação.
* **Atalho para Formatar no VS Code**: `Shift + Alt + F` (Windows/Linux) ou `Option + Shift + F` (macOS).



### C. Validadores Online

* **YAML Lint**: [yamllint.com](https://www.yamllint.com/) — Cole o conteúdo para verificar erros instantaneamente.

## 3. Armadilhas Comuns de Formatação

| Erro | Exemplo Incorreto | Exemplo Correto | Motivo do Erro |
| --- | --- | --- | --- |
| **Uso de TAB** | `\taluno: João` | `  aluno: João` | O parser do YAML rejeita caracteres `TAB`. |
| **Falta de Espaço** | `idade:20` | `idade: 20` | Sem o espaço após `:`, o texto é lido como string única. |
| **Booleano em maiúscula** | `ativo: TRUE` | `ativo: true` | O padrão YAML/Kubernetes prefere booleans em minúsculo. |
| **Número como String** | `versao: 1.0` | `versao: "1.0"` | Sem aspas, `1.0` pode ser interpretado como float. |

## Exemplo
```yaml

# NÍVEL 1: Objeto Raiz (Representa a organização/infraestrutura global)
datacenter:
  nome: "DC-SaoPaulo-01"
  pais: "Brasil"

  # NÍVEL 2: Lista de Regiões dentro do Data Center
  regioes:
    - nome: "sa-east-1"
      ativo: true

      # NÍVEL 3: Lista de Racks Físicos dentro da Região
      racks:
        - id_rack: "RACK-A01"
          fileira: 4

          # NÍVEL 4: Lista de Servidores Físicos dentro do Rack
          servidores:
            - hostname: "srv-db-prod-01"
              ip_privado: "192.168.10.50"

              # NÍVEL 5: Objeto de Hardware pertencente a ESTE servidor
              hardware:
                memoria_gb: 512
                processador:
                  modelo: "Intel Xeon Platinum"
                  cores: 64

              # NÍVEL 5: Lista de Aplicações/Serviços rodando NESTE servidor
              aplicacoes:
                - nome_app: "PostgreSQL"
                  porta: 5432

                  # NÍVEL 6: Dicionário de Parâmetros da Aplicação
                  configuracoes_sistema:
                    max_conexoes: 1000
                    shared_buffers: "64GB"
                    ssl_habilitado: true

                - nome_app: "Redis-Cache"
                  porta: 6379
                  configuracoes_sistema:
                    max_memory: "16GB"


```

## 4. Lab Prático: Cadastro de Alunos

### Objetivo

Estruturar dados de uma turma e de seus respectivos alunos no formato YAML correto e realizar a validação sintática do arquivo.

### Instruções do Desafio

Crie um arquivo chamado `alunos.yaml` contendo os dados abaixo respeitando a hierarquia:

1. **Dados Gerais da Turma** (Dicionário):
* `turma`: `DevOps 2026`
* `semestre`: `1`
* `ativa`: `true`


2. **Lista de Alunos** (`alunos` - Lista de Objetos):
* **Aluno 1**:
* `id`: `101`
* `nome`: `Carlos Eduardo`
* `email`: `carlos@email.com`
* `disciplinas`: lista contendo `Docker`, `Kubernetes` e `Helm`
* `endereco`: dicionário com `cidade`: `São Paulo` e `estado`: `SP`


* **Aluno 2**:
* `id`: `102`
* `nome`: `Mariana Lima`
* `email`: `mariana@email.com`
* `disciplinas`: lista contendo `Linux` e `Kubernetes`
* `endereco`: dicionário com `cidade`: `Campinas` e `estado`: `SP`



---

### Passo de Validação do Lab

Após salvar o arquivo `alunos.yaml`, execute a validação via terminal:

```bash

yamllint alunos.yaml

```

Se o retorno for **`YAML Válido!`**, a estrutura do arquivo está correta e pronta para uso.
